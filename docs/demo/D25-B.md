## 准备与复现

1. 从干净检出固定候选启动，按 `docs/environment.md` 与 `docs/evaluation-edit-handoff.md` 准备锁定 Node/pnpm、Java、Docker、Chromium。使用原批次、原应用、原不可变版本；不能导入源码冒充原版本。确认原批次 API 提交与本轮候选一致，否则登记候选不一致并停止计分。
2. A 提供原批次路径、保留责任人/窗口、owner 会话和 admin 账本读取权限。私密值只通过环境传入；不展示终端环境、Cookie、登录凭据或个人数据。
3. 执行 `node evals/browser/record-command.mjs batch <原批次目录>`；保存 report。执行 `node evals/edit/handoff.mjs <原批次目录> <report.json> <新预检目录>`。BLOCKED 时展示原因并停止依赖操作，预检 READY 也不计编辑成功。
4. 仅在前提齐全时，使用平台界面完成下表操作。每项展示任务终态、前后版本、前后截图、源码差异及未涉及文件摘要。失败保存错误和日志，不刷新重发未知任务。SHOW-01 依次 EDIT-01→02→03→05，后项基于前项已证明的新版本；04/06 独立进行。
5. 终态后按交接协议填写 task-index.json，运行 `node evals/edit/collect.mjs <批次> <task-index.json> <新采集目录>`，再执行 `node evals/browser/record-command.mjs batch <批次> --edit-records <新采集目录>`。保留失败、未知 usage 和原版本快照。
