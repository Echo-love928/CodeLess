## PR #11 同伴审查与 root 宿主修复

A 对 `e304125` 提交了 `CHANGES_REQUESTED` 审核：Linux 宿主 worker 若以 root 运行，旧 `build.mjs` 会将 `--user 0:0` 传给 Docker，违反构建容器非 root 条件。修复在 `services/runner/src/template/build.mjs` 入口先计算容器用户；宿主 UID 或 GID 为 0、非安全整数时立即报错，且在创建输出目录和启动 Docker 之前结束。非 root Linux 继续沿用宿主 UID/GID 以写入输出目录；无 POSIX UID/GID 的 Windows 继续使用 `1000:1000`。

`tests/runner/template/acceptance.test.mjs` 新增 root 身份回归：`0:0`、`0:1000`、`1000:0` 均被拒绝，`1001:1001` 保持可用。定向 `node --test --test-name-pattern "root host identity" tests/runner/template/acceptance.test.mjs` 退出 0（1/1）；完整 `node --test tests/runner/template/acceptance.test.mjs` 退出 0（6/6）；`corepack pnpm verify:runner` 退出 0（14/14），三个 fixture 和原四项验收均通过。A 复查本次变更及受影响测试后再决定批准；本人不自批、不合并。

A 的环境建议也已记录：若宿主配置只监听 `127.0.0.1` 的代理，Docker 构建容器无法直接使用该地址；本次验证没有修改代理配置，若复现此类下载失败，应仅为验证进程清除相应代理环境变量或配置 Docker 可达代理，不将环境失败计为测试通过。
