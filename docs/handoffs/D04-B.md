## 接口对齐与真实联调阻塞

- 当前 `contracts/openapi.v0.json` 仅定义 `POST /api/v0/applications` 与 `GET /api/v0/applications/{applicationId}`；`services/api` 当前没有生产应用 CRUD handler。D04-A 分支/PR 在本地不可见。`gh pr list` 返回 HTTP 401，`git ls-remote --heads origin` 返回 Windows 凭据错误，故不能读取 D04-A PR、测试报告或运行真实创建链。
- 本分支待对齐的**列表契约提案**：`GET /api/v0/applications?page=0&size=20`，响应 `{ "items": Application[], "page": 0, "size": 20, "total": 0 }`。页面按本页搜索并据 `total` 分页。D04-A 需确认路径、字段、排序及错误码；若采用不同契约，最后启用功能的 PR 应调整客户端和 fixture，并做真实联调。此提案未写入公共 OpenAPI。
- `latestReadyVersionId` 是现有 Schema 唯一的应用版本标识，不能冒充初始草稿版本。若 D04-A 创建初始草稿版本，请明确响应中的草稿版本字段或独立查询接口，再补工作台显示和验收。
- 真实验收应启动 D04-A 的 API 与 PostgreSQL，使用已鉴权演示账号经 Vite `/api/` 代理执行登录→创建→详情工作台，并以另一账号验证详情 404、空列表、服务错误与重复点击。当前浏览器用例均标注为 **contract fixture**，不能证明该真实链路。
