# CodeLess UI 优化方案

## 设计目标

面向学生、社团和小型组织，帮助用户快速找到自己的应用、查看成果并做小幅调整。视觉定位是安静、清楚、有作品感的创作工具。方案先在独立 HTML 中验证，现已应用到 `apps/web` 的 Vue 页面。

## 当前问题与处理

| 当前表现 | 优化方式 |
| --- | --- |
| 蓝色画布、蓝色缩略图、蓝色装饰重复 | 中性灰白承载工具界面，蓝色仅用于主要动作和选中态 |
| 大号计数、英文眉题、阶段条分散注意力 | 用中文标题、紧凑状态摘要和明确的更新时间建立层级 |
| 缩略图只有占位色块，应用辨识度低 | 展示与工作台一致的真实内容缩略图 |
| 工作台被标题、流程和说明挤占 | 采用紧凑顶栏、页面导航、连续预览画布、上下文属性面板 |
| 到处解释接口和实现进度 | 原型顶部统一标注演示范围，产品内仅保留必要的操作反馈 |
| 未选中时属性面板缺少有效引导 | 给出具体的选择动作；选中后可在当前页面即时修改文案 |

## 设计系统

- 颜色：画布 `#F5F6F8`，面板 `#FFFFFF`，正文 `#222936`，次级文字 `#687181`，操作蓝 `#4263EB`，边线 `#E3E6EC`。示例社团页面独立使用浅鼠尾草绿，以区分工具界面和作品内容。
- 字体：品牌使用 Trebuchet MS；中文标题和正文使用系统无衬线（Microsoft YaHei / PingFang SC）；日期和尺寸用 Consolas。无外部字体请求，离线可打开。
- 层级：页面标题 30–34px，区块标题 18px，正文 13–15px，辅助文字 12px。取消中文负字距；品牌字距单独处理。
- 布局：桌面侧栏 204px；内容最大宽度 1160px；24–32px 主间距；控件 6–8px 圆角，主要面板 12px 圆角。阴影只用于浮层和预览画布。
- 识别特征：社团作品采用“校园活动邀请函”式排版和折页插画，同一内容同时用于列表缩略图、工作台与登录展示，让产品围绕具体作品形成辨识度。
- 动效：只有短暂颜色和边框反馈；支持减少动态效果、键盘焦点和小屏布局。

## 页面结构

```text
应用列表：导航 | 页标题 + 新建 → 最近应用实景预览 | 需求起步区 → 三种场景入口
工作台：返回 + 应用名 + 发布 → 页面列表 | 最大化页面预览 | 选中元素属性
登录入口：品牌 → 具体作品展示 | 简洁入口 → 本地演示说明
```

方案自检：不采用居中大口号搭配发光输入框的常见 AI 产品布局；首页把已有作品放在首位。作品插画与校园活动内容相关，不使用与任务无关的漂浮图形。新增场景入口、需求输入和设备切换属于设计提案，未声称现有系统已经实现。

## HTML 原型与 Vue 实施范围

- 顶部切换三种页面，支持 URL hash 直达。
- 应用列表可搜索示例应用，打开工作台；场景入口填入需求，新建按钮聚焦需求输入。
- 需求提交只展示明确的原型反馈，不调用生成服务。
- 工作台可切换桌面/手机、选择标题或按钮、修改文案、取消选择，支持就绪/加载/空态/错误态预览。
- 发布保持禁用。没有账号请求、真实保存、部署或模型调用；刷新后恢复示例。
- 登录页提供演示入口；账号登录明确标注尚未开放。
- Vue 实施复用了作品页面、品牌和图标组件；新增与先前概念相符的 SVG favicon。真实数据与服务端操作仍等待接口接入。

## 后续实施顺序

1. 确认此 HTML 的布局与视觉方向，提取颜色、排版、间距与控件变量。
2. 优先应用到 AppsView，再迁移 WorkbenchView 与 LoginView。
3. 将工具栏、项目卡片、属性字段和状态反馈拆成可复用组件，保留既有路由及 StatePanel 语义。
4. 新建、保存、生成和发布在接口能力就绪后接入；设计预览中的演示数据不进入正式数据层。

## 验收重点

桌面 1440px 与手机 390px 检查无横向溢出；验证页面切换、搜索无结果、需求校验、即时文案编辑及状态恢复；检查浏览器异常。交付 PNG 均由 HTML 浏览器渲染得到。
